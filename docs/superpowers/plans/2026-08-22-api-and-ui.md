# API and Web UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web app — highlight feed on top, day-by-day agenda below — served by the same process that runs the sweep on a schedule.

**Architecture:** A read-model layer turns stored screenings into grouped view data. A Hono API serves JSON and the built static assets. A React + Vite UI renders Layout A. An in-process scheduler runs the sweep, resolve, and score passes every 6 hours.

**Tech Stack:** Hono, React 19 + Vite, TypeScript, Vitest. No deployment in this plan — `npm run serve` on localhost.

**Spec:** `docs/superpowers/specs/2026-08-16-cinema-tracker-design.md`
**Read first:** `AGENTS.md`

## Scope

In scope: tag weights for `ARTHOUSE`/`EVENT`, read models, HTTP API, web UI, health view, "new since you last looked", the scheduler, and `npm run serve`.

Out of scope: deployment, ICS feed, push digest, LLM tag extraction, watchlist pruning, auth.

## Design direction — follow this precisely

The UI is a **repertory cinema programme**, not a streaming grid. Printed-calendar
aesthetic: paper, ink, hairline rules, dense typographic hierarchy. This is a
deliberate rejection of the generic dark movie-app look, and it fits the domain —
the owner's interest is repertory and special formats.

**Do not** substitute a different aesthetic, a component library, Tailwind's default
look, purple gradients, or system fonts. Write real CSS.

### Tokens

```css
:root {
  --paper:        #F4F1EA;   /* warm off-white ground */
  --paper-sunk:   #EBE7DD;   /* recessed panels, agenda stripes */
  --ink:          #151310;   /* primary text */
  --ink-soft:     #55504733; /* hairline rules (alpha) */
  --ink-muted:    #6B6459;   /* metadata, secondary text */
  --accent:       #D6482B;   /* vermilion — special formats ONLY */
  --accent-sunk:  #A8351C;
  --gold:         #9A7B3F;   /* watchlist marks, sparing */
}
```

Vermilion is reserved. It marks `70MM`, `35MM`, `LIVE_SCORE`, `Q_AND_A` — the things
worth crossing town for. If everything is vermilion, nothing is.

### Type

Load from Google Fonts:

- **Bodoni Moda** — film titles and the masthead. A didone: the typography of film
  posters and programme notes. Titles set large, tight leading, optical sizing on.
- **Archivo Narrow** — metadata, labels, venue names. Condensed, so dense rows stay
  readable.
- **IBM Plex Mono** — showtimes and dates. Tabular figures so times align in columns
  like a printed schedule.

Small-caps labels: `Archivo Narrow`, `text-transform: uppercase`,
`letter-spacing: 0.12em`, `font-size: 0.6875rem`, `color: var(--ink-muted)`.

### Composition

- **Masthead:** the words `CINEMA TRACKER` in Bodoni at scale, the date range beneath
  in mono, a 2px ink rule under the whole thing. Asymmetric — masthead left, sweep
  freshness right.
- **Highlight entries:** each preceded by a hairline rule. Rank numeral in the left
  margin in mono, ink-muted, large. Title in Bodoni ~2rem. Beneath: director, year,
  runtime in Archivo Narrow. Then venue(s) and showtimes in mono. Score reasons as
  small-caps chips.
- **Format stamps:** vermilion, `1px solid`, uppercase mono, `letter-spacing .08em`,
  `padding: 2px 7px`, `transform: rotate(-1.5deg)`, no fill. They should read as
  rubber stamps on paper.
- **Agenda:** date as a large mono numeral in a left margin column, films hanging to
  its right. Alternate row grounds with `--paper-sunk` at low opacity. Times as
  underlined mono links.
- **Texture:** a subtle SVG grain overlay at ~3% opacity, `pointer-events: none`,
  fixed position. This is what makes it read as paper rather than as a beige web page.

### Motion

Restrained. One staggered fade-and-rise on load for highlight entries
(`animation-delay` stepped ~40ms by index). Showtime links fill vermilion on hover.
Nothing else. No parallax, no scroll-jacking, no spinners that outlive their request.

### Responsive

Must work on a phone. Below 640px the rank numeral moves inline above the title, the
agenda's margin column collapses to a full-width date header, and showtimes wrap.

### Task 2: Read models

**Files:** Create `src/read/highlights.ts`, `src/read/agenda.ts`, `src/read/health.ts`; tests for each.

This is where the anniversary-flooding presentation problem gets fixed. **Group by
film, not by screening.** One entry per film per venue-cluster, carrying its showtimes.

- [ ] **Step 1: Write failing tests** covering:

  `getHighlights(db, { from, to, limit })` →
  ```ts
  interface HighlightEntry {
    filmId: number | null
    title: string           // resolved film title, else raw title
    rawTitle: string
    year?: number
    director?: string
    runtimeMinutes?: number
    posterUrl?: string
    score: number
    reasons: { label: string; weight: number }[]
    tags: string[]
    venues: { id: string; name: string; chain: string }[]
    showtimes: { id: number; startsAtUtc: string; localDate: string; ticketUrl: string; venueId: string }[]
    firstSeenAt: string
    isNew: boolean          // firstSeenAt > app_state.last_visit_at
  }
  ```
  - Groups multiple screenings of one film into a single entry.
  - Groups by `film_id` when resolved, and by `raw_title` when not — **this is why
    the eight Star Trek double features appeared sixteen times.**
  - Orders by score descending, then by earliest showtime.
  - Excludes cancelled screenings and anything in the past.
  - `isNew` is true only when `first_seen_at` is later than `app_state.last_visit_at`;
    when that key is absent, `isNew` is false for everything (not true).
  - Respects `limit`.
  - Returns `[]` cleanly on an empty database.

  `getAgenda(db, { from, to })` → days, each with entries grouped by film, ordered by
  first showtime. A day with no screenings is omitted, not rendered empty.

  `getHealth(db)` → per-source status from `evaluateHealth`, last run time, plus
  unresolved title counts.

- [ ] **Step 2:** Run; see them fail.
- [ ] **Step 3:** Implement. Keep these **pure reads** — no writes, no fetching.
- [ ] **Step 4:** Run; green.
- [ ] **Step 5:** Run each read model against the live database and print the first
      three entries. **Confirm the Star Trek double features now appear once each,
      not twice**, and that a film showing at four venues is one entry with four
      venues rather than four entries.
- [ ] **Step 6:** Commit — `feat: add read models grouping screenings by film`

### Task 3: HTTP API

**Files:** Create `src/server/app.ts`; test `tests/server/app.test.ts`

```
GET  /api/highlights?days=14&limit=40
GET  /api/agenda?from=&to=
GET  /api/health
POST /api/visit          → stamps app_state.last_visit_at, returns the previous value
GET  /api/venues
```

- [ ] **Step 1: Write failing tests** using Hono's `app.request()` — no real socket.
      Cover: each route returns 200 and well-formed JSON; `days` and `limit` are
      validated and clamped (a negative or absurd `limit` must not reach the query);
      an unknown route returns 404 as JSON, not HTML; `POST /api/visit` returns the
      prior timestamp and updates the stored one; a read-model throw returns 500 with
      a JSON error body rather than an empty response.
- [ ] **Step 2:** Run; see them fail.
- [ ] **Step 3:** Implement. `createApp(db)` returns a Hono app — **do not** open the
      database inside the app; inject it, so tests can pass an in-memory instance.
- [ ] **Step 4:** Run; green.
- [ ] **Step 5:** Commit — `feat: add JSON API`
